# Architecture decisions

Use this log when a change affects navigation, customer data, stage progression, permissions, storage or shared UI. Write the decision before implementation; distinguish accepted choices from proposals. Never silently rewrite an accepted decision: add a superseding ADR. Small visual fixes do not need an ADR.

| ADR | Status | Decision |
| --- | --- | --- |
| [0001](0001-customer-workspace.md) | Accepted, 2026-10-22 | Full-width Customers and customer workspace; customer actions stay in the record |
| [0002](0002-project-management.md) | Accepted, 2026-10-22 | Stage Kanban; only next-stage moves, with confirmation |
| [0003](0003-completed-and-trash.md) | Accepted, 2026-10-22 | Separate Completed; recoverable Trash with retained payment history |

Each entry records context, decision, alternatives, consequences and checks. Update the feature/access checklist after delivery. Changes to these choices require another discussion.
